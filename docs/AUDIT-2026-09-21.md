## 一、本次已修复（3 项）

### 1. 静态资源层完全缺失安全响应头 —— 已修 ✅

**问题**：`node-functions/lib/http.js` 给 **API 响应**加齐了安全头，但 `edgeone.json` 里**没有任何 headers 配置** —— 也就是说用户实际访问的 HTML / JS / CSS（静态层）**一个安全头都没有**。这属于"防护加在了看不见的地方，真正暴露的页面层反而裸奔"。

**修复**（`edgeone.json` 新增 `headers`，EdgeOne 官方支持该字段）：

| 头 | 值 | 作用 |
|---|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; …` | 防 XSS 注入执行 |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | 强制 HTTPS，防降级 |
| `X-Frame-Options` | `DENY` | 防点击劫持 |
| `X-Content-Type-Options` | `nosniff` | 防 MIME 嗅探 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 收紧 referrer 泄露 |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=(), payment=()` | 关闭用不到的浏览器能力 |

同时补了缓存策略：`/assets/*` → `max-age=31536000, immutable`（Vite 产物带 hash，可长缓存）；`/index.html` → `no-cache`（否则用户会拿到旧壳）。

**验证**（线上实测 11/11 通过）：6 个安全头全部生效；**CSP 未打断任何功能**——遍历 21 个路由全部正常渲染、**零 CSP 违规、零 JS 运行时错误**。

> ⚠️ 后续维护铁律：改 CSP 必须重跑全站 console 回归（见第五节命令），CSP 是最容易"修了安全问题、顺手搞坏功能"的头。

### 2. 前端缺全局错误处理 —— 已修 ✅

**问题**：`src/main.js` 从未配置 `app.config.errorHandler`。Vue 的默认行为是：**未捕获的组件异常会中断该组件树的渲染**，用户看到的是空白或半截页面，且控制台之外没有任何兜底。项目此前多处"页面空白"现象与此机制有关。

**修复**：`main.js` 补 `app.config.errorHandler` + `window.addEventListener('unhandledrejection')`，统一记录 `[vue-error]` / `[unhandled-rejection]`。**刻意不弹窗**——业务错误已由 `api/request.js` 统一提示，重复弹窗只会打扰用户。

### 3. 懒加载 chunk 失效无兜底（部署后白屏）—— 已修 ✅

**问题**：本项目 26 个路由中 22 个走 `() => import()` 懒加载，且**部署非常频繁**（改一行 CSS 也会重新构建、产物 hash 全变）。典型故障场景：用户停在旧页面 → 新版本部署完成 → 用户点击进入新路由 → 浏览器去请求**已被替换的旧 chunk** → 404 → 动态 import 抛错 → **整页白屏**。此前 `router` 里没有 `onError`，这个场景没有任何兜底。

**修复**（`src/router/index.js`）：`router.onError` 捕获 `Failed to fetch dynamically imported module` 等错误 → 自动硬刷新一次拿最新 `index.html`；用 `chunkReloaded` 标志位防止刷新循环。

**P1-5 校园邮箱密码明文入库 + 明文导出且无审计**（2026-09-21 追加，实测核实）
- 背景核实：**登录口令不是明文**——`sys_user.password_hash` 为 bcrypt（实测 490 条全部 `$2a$10$…`、60 字符，0 条非 bcrypt）；刷新令牌存 `SHA-256`（实测 64 字符齐全）；邮箱验证码有 10 分钟时效（`expires_at < NOW()` 在 SQL 侧判定，`register.js:65` / `forgot-reset.js:42`）。这三处无问题。
- 问题：`sys_user.mail_password VARCHAR(64)` 存**明文**，代码中无任何加解密（全库 grep `encrypt|decrypt|cipher|aes` 为空）。实测 2 条已开通邮箱的记录，库里就是可读明文（如 `admin@keaidang.com` 对应的一串 12 位密码）。
- **这是刻意的设计**（schema 注释自述"管理员可见可导出"），因为它是第三方邮箱服务的凭据，业务上需要在用户忘记时能取回。但也意味着：
  - `GET /api/admin/mailbox?export=csv` 会把**全站邮箱密码明文**导成 CSV（`mailbox.js:40`）；
  - `UserManageView` 有「密码」按钮直接弹窗展示明文（`:393`）；
  - 用户可自行改自己的邮箱密码（`/api/me/mail-password`）。
- **附带发现（独立缺陷）**：`mailbox.js` 的 4 个写操作（enable/disable/resetPassword/updateAddress）都调了 `opLog` 留痕，但 **GET 分支（含明文 CSV 导出）在 `mailbox.js:34-50` 直接 return，没有任何 `opLog`** —— `requireRoles` 自身也不写日志（`guard.js:48-64` 仅做校验）。即"一键导出全校邮箱明文密码"这个最敏感的动作**零审计留痕**。
- 风险量化：泄露后攻击者可登录用户校园邮箱并以学校名义发信；且导出动作无法追溯是谁导的。属"内部人员误用/越权不可追溯"类风险。
- 建议（按性价比）：
  1. **✅【已于 2026-09-21 修复，commit 461517b】给明文导出与查看补 `opLog`，同时堵住列表下发明文**
     - 实施时发现只给导出加日志**等于摆设**：`GET /api/admin/mailbox` 原本对管理员直接返回全量 `mail_password`，前端「查看密码」也是"重新拉整个列表再挑一条"——管理员照样能静默批量取走全部明文。故三处一起改：
       - CSV 导出前写 `opLog('mailbox.export', count)`；
       - **新增 `POST action=viewPassword`** 读取单个用户密码并写 `opLog('mailbox.viewPassword', user:<id>, 邮箱地址)`；
       - **GET 列表一律剥离 `mail_password`**（含管理员），前端改调 `viewPassword`。顺带删掉 `requireRoles` 之后恒为真的死分支。
     - 上线验收 23 项全过（后端 15 + 浏览器端到端 8）：列表 490 条零密码字段、viewPassword 返回 12 位密码、CSV 仍带 2 条明文、两个动作各新增一条 opLog、学生调用均 40301 被拒。
     - 审计口径已写入 `docs/API.md`（新增"邮箱密码审计口径"行）：明文只从 CSV 导出与 `viewPassword` 两条路径出去，二者均留痕；排查"谁看过/导过密码"查 `sys_op_log` 的这两个 action。
  2. **【待决策】改为 AES-256-GCM 可逆加密存储**：密钥放环境变量，读写两侧加解密。管理员仍能查看（业务不变），但库被拖走时不是明文，且能发现是否被人篡改。改动约 30 行 + 4 个读写点 + 迁移存量 2 行。**需要先确认密钥保管方式**（丢失则邮箱密码不可恢复，只损失"查看"能力不影响用户登录邮件系统）。
  3. 不可选项：改不可逆哈希——业务上必须能取回展示，不可行。

## 四、结论

- **功能与数据是健康的**：没有孤儿数据、没有状态不一致、没有注入面、没有鉴权漏洞、没有依赖漏洞、移动端 22 个页面零溢出、线上零新增错误。
