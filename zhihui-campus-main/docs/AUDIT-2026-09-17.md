## 一、发现并修复的问题

### P1 · 辅导员可架空"本院数据范围"（越权）
- **位置**：`node-functions/api/admin/users.js` → `setProfile`
- **问题**：辅导员传 `deptId=null` 可把本院用户的 `dept_id` 置空 → 该用户脱离"本院"数据范围（scope 失效）；且 `classId` 可挂到任意院系的班级（跨院数据污染）
- **修复**：院系归属只有超管可改（辅导员强制维持原院系）；`classId` 服务端校验必须属于所选院系；前端归属弹窗的院系下拉对非超管禁用

### P2 · 管理端敏感操作无审计留痕
- **位置**：改角色 / 禁用账号 / 改归属 / 院系维护
- **修复**：新增 `sys_op_log` 审计表（operator_id / action / target / detail / ip / created_at），`guard.js` 提供 `opLog()`，上述操作全部落库；审计写失败不阻断业务但打印服务端日志

### P2 · 保留用户名未设防
- **位置**：`register.js`
- **问题**：`root / administrator / system` 等用户名可被任意抢注（仿冒钓鱼面）
- **修复**：新增 `RESERVED_NAMES` 黑名单（admin/root/administrator/system/sysop/operator/support/master），命中返回 41002

### P2 · 仓库卫生（误提交 + 白名单漏配）
- **问题**：`git add -A` 把调试探针（probe*/canary*）、本地验证临时文件（*.txt）提交入库；`.gitignore` 的 scripts 白名单漏掉 `migrate.mjs / grant-role.mjs`（新工具脚本根本没进仓库）
- **修复**：`git rm --cached` 清除 18 个临时文件；`.gitignore` 增加探针/报告类通配规则并补齐脚本白名单
- **核实**：被清理文件均不含密钥/口令（.env 始终只在本地）

## 五、稳定性压测与随机 500 治理（追加）

审计期间的线上压测暴露了另一个问题：**同一请求（如 setProfile 查不存在的用户）随机返回 400/500，与输入内容无关**，本地同参数复现不出。

- **定位**：判为 TiDB Serverless 建连/代理层抖动（ECONNRESET / malform packet / 瞬时连接数），部分请求在第一跳失败
- **治理**（`lib/db.js`）：
  1. 瞬时错误识别集合（连接重置/丢失、握手、SSL、连接数上限、malform packet）
  2. `query()` 命中瞬时错误 → 换连接自动重试（最多 2 次，150ms 间隔）
  3. 连接池 `connectionLimit` 8→5，降低免费层并发压力
- **诊断兜底**：`jsonError` 将 500 错误落库 `sys_op_log`（action='error.500'），线上无控制台也能远程查真实错误
- **验收**：修复前三轮混发 400/500 交替 → 修复后 **15/15 全部 400**（零 500），错误落库位零触发
- **教训沉淀**：TiDB Serverless 下瞬时网络错误是常态，所有 DB 调用必须自带重试韧性；随机性故障要靠"批量连发 + 错误落库"定位，盲猜单次现象没有意义
